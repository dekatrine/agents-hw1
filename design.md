# Данные и расчёты

## Формат результата реализации

Один `tracker-v2.html` содержит разметку, стили и JavaScript. Внешние библиотеки, CDN и API-ключи не используются. В текущем запросе файл реализации не создаётся.

## Модель данных

Основное состояние — список задач. Каждая задача содержит:

| Поле | Значение |
| --- | --- |
| `id` | Уникальный стабильный идентификатор задачи |
| `title` | Непустое название после удаления пробелов по краям |
| `hours` | Конечное число от 0,5 до 24 включительно, кратное 0,5 |
| `done` | Логический признак выполнения |

Стартовый список:

| Название | Часы | Выполнено |
| --- | --- | --- |
| Чтение | 2 | Да |
| Практика | 4 | Нет |
| Повторение | 2 | Нет |

Каждая стартовая задача также получает собственный `id`. Удаление и переключение выполнения адресуются по `id`, чтобы корректно работать и в отфильтрованном списке.

Отдельно от задач хранятся текущий фильтр, введённые значения формы и ошибки полей. Фильтр имеет три состояния: «Все» показывает все задачи, «Активные» — задачи с `done=false`, «Готовые» — задачи с `done=true`.

## Проверка и изменение данных

Перед добавлением проверяются оба поля. Название проверяется после `trim`. Для часов сначала проверяется, что ввод не пуст и не состоит только из пробелов, затем — числовое значение, конечность, диапазон и шаг 0,5. Пустой ввод не преобразуется в ноль.

При ошибках список задач не меняется. Ошибки показываются у соответствующих полей; исходные значения обоих полей остаются в форме. При успешном добавлении создаётся задача с новым `id`, очищенным по краям названием, числовыми часами и `done=false`.

Удаление убирает задачу из основного списка. Переключение меняет её `done` на противоположное значение. После успешного изменения заново формируются видимый список и показатели.

## Расчёты

- Все часы = сумма `hours` по всему списку задач.
- Выполненные часы = сумма `hours` по задачам с `done=true`.
- Если все часы больше нуля: прогресс = округление до ближайшего целого числа от `100 × выполненные часы / все часы`, с округлением половины вверх.
- Если задач нет: все часы = 0, выполненные часы = 0, прогресс = 0%.

Допустимые задачи имеют положительные часы, поэтому нулевая сумма соответствует пустому списку. Деление при нулевой сумме не выполняется.

Фильтр применяется только при построении видимого списка. В расчёты всегда передаётся основной список целиком. Поэтому скрытие «Чтения» фильтром «Активные» оставляет 2/8 ч и 25%. Фильтр «Готовые» в стартовом примере показывает только «Чтение», а показатели остаются 2/8 ч и 25%. Выполнение «Практики» меняет показатели на 6/8 ч и 75%.

## Интерфейс

Интерфейс содержит показатели часов и прогресса, переключение фильтра, список задач с управлением выполнением и удалением, форму названия и часов. Поля и кнопки имеют понятные подписи, ошибки расположены рядом с полями. Компоновка и перенос текста позволяют пользоваться интерфейсом при ширине 390 px без горизонтального скролла.

## Необязательное сохранение

Базовый вариант хранит задачи в памяти и при новом открытии показывает стартовый пример. Дополнительно можно сохранять список задач в `localStorage` после добавления, удаления и переключения выполнения и восстанавливать его при открытии. Сохранённый пустой список отличается от отсутствия сохранения: пустой список не заменяется примером.

Если чтение или запись хранилища недоступны, показывается понятное сообщение: «Не удалось использовать хранилище. Изменения доступны в текущем открытии страницы, но могут не сохраниться после закрытия». При отсутствии восстановленных данных используется стартовый пример; если задачи уже находятся в памяти, работа продолжается с ними.

При открытии через `file://` поведение `localStorage` зависит от браузера. Сохранение между перезапусками является дополнительным улучшением и в этом режиме не гарантируется.
