# Спецификация мини-трекера

## ADDED Requirements

### Requirement: Автономный файл

Мини-трекер MUST работать из одного файла `tracker-v2.html` со встроенными CSS и JavaScript, без CDN, внешних библиотек и API-ключей.

#### Scenario: Открытие локального файла

- WHEN пользователь открывает `tracker-v2.html` локально без доступа к сети
- THEN доступны добавление, удаление, переключение выполнения, фильтр и расчёт показателей.

### Requirement: Данные и стартовый пример

Каждая задача MUST содержать уникальный `id`, название `title`, числовые часы `hours` и логический признак `done`. Начальное состояние MUST содержать «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`.

Если дополнительное сохранение реализовано, стартовый пример используется при отсутствии ранее сохранённых задач. Сценарии со стартовым примером проверяются без сохранённых данных.

#### Scenario: Стартовый пример

- WHEN трекер инициализирован стартовым примером
- THEN всего запланировано 8 ч, выполнено 2 ч, прогресс равен 25%.

### Requirement: Изменение задач

Добавление, удаление и переключение `done` MUST изменять данные задач. Новая задача MUST получать уникальный `id`, название после `trim`, допустимые часы и `done=false`. Список и показатели MUST отражать актуальные данные после каждого изменения.

#### Scenario: Добавление задачи

- WHEN пользователь добавляет задачу с названием «  Конспект  » и часами 1,5
- THEN в данных появляется новая невыполненная задача «Конспект» на 1,5 ч, а итоговые показатели пересчитываются.

#### Scenario: Удаление задачи

- WHEN пользователь удаляет задачу
- THEN задача с соответствующим `id` исчезает из данных и списка, а итоговые показатели пересчитываются.

#### Scenario: Выполнение практики

- WHEN в стартовом примере пользователь отмечает «Практику» готовой
- THEN её `done` становится `true`, выполнено 6 ч из 8 ч, прогресс равен 75%.

#### Scenario: Отмена выполнения

- WHEN пользователь повторно переключает выполненную «Практику» из предыдущего сценария
- THEN её `done` становится `false`, выполнено 2 ч из 8 ч, прогресс равен 25%.

### Requirement: Проверка формы

Название после `trim` MUST быть непустым. Часы MUST быть конечным числом от 0,5 до 24 включительно с шагом 0,5. Пустой ввод часов, включая одни пробелы, MUST считаться отсутствующим значением, а не нулём. При недопустимом вводе задача MUST NOT добавляться; ошибка MUST быть видна рядом с соответствующим полем, а введённые значения обоих полей MUST сохраняться.

#### Scenario: Пустое название

- WHEN пользователь отправляет форму с пустым названием или названием только из пробелов
- THEN задача не добавляется, рядом с названием видна ошибка, значения формы сохраняются.

#### Scenario: Пустые или отрицательные часы

- WHEN пользователь отправляет форму с пустыми часами или отрицательным числом часов
- THEN задача не добавляется, рядом с часами видна ошибка, значения формы сохраняются.

#### Scenario: Недопустимые часы

- WHEN часы не являются конечным числом, равны 0, меньше 0,5, больше 24 или не соответствуют шагу 0,5
- THEN задача не добавляется, рядом с часами видна ошибка, значения формы сохраняются.

#### Scenario: Допустимые границы

- WHEN пользователь вводит непустое название и 0,5 либо 24 часа
- THEN задача успешно добавляется.

### Requirement: Итоговые показатели

Трекер MUST считать сумму часов всех задач и сумму часов задач с `done=true`. Прогресс MUST равняться округлению до ближайшего целого значения `100 × выполненные часы / все часы`; половина округляется вверх. При отсутствии задач все часы, выполненные часы и прогресс MUST равняться нулю; `NaN` и `Infinity` MUST NOT отображаться.

#### Scenario: Удаление всех задач

- WHEN пользователь удаляет все задачи
- THEN список пуст, всего 0 ч, выполнено 0 ч, прогресс 0%, без `NaN` и `Infinity`.

### Requirement: Фильтр списка

Фильтр MUST влиять только на видимый список. Режим «Все» MUST показывать все задачи, режим «Активные» MUST показывать только задачи с `done=false`, режим «Готовые» MUST показывать только задачи с `done=true`. Итоговые часы и прогресс MUST рассчитываться по всем задачам при любом фильтре.

#### Scenario: Активные задачи стартового примера

- WHEN в стартовом примере включён фильтр «Активные»
- THEN видны «Практика» и «Повторение», всего остаётся 8 ч, выполнено 2 ч, прогресс остаётся 25%.

#### Scenario: Готовые задачи стартового примера

- WHEN в стартовом примере включён фильтр «Готовые»
- THEN видно только «Чтение», всего остаётся 8 ч, выполнено 2 ч, прогресс остаётся 25%.

### Requirement: Читаемый интерфейс

Интерфейс MUST оставаться читаемым при ширине 390 px без горизонтального скролла. Поля и кнопки MUST иметь понятные подписи.

#### Scenario: Узкий экран

- WHEN ширина области просмотра равна 390 px
- THEN список, показатели, поля, ошибки и кнопки доступны для чтения и использования без горизонтального скролла.

### Requirement: Поведение дополнительного сохранения

Сохранение в `localStorage` не входит в обязательную приёмку. Если оно реализовано, задачи MUST сохраняться после изменений и восстанавливаться при следующем открытии, когда хранилище доступно. Сохранённый пустой список MUST восстанавливаться как пустой. При недоступном хранилище интерфейс MUST показывать понятное сообщение и продолжать работу с задачами в памяти. Ограничение для `file://` MUST быть описано: поведение хранилища зависит от браузера.

#### Scenario: Недоступное хранилище при включённом сохранении

- WHEN чтение или запись `localStorage` недоступны
- THEN пользователь видит понятное сообщение, а добавление, удаление, переключение выполнения, фильтр и расчёты продолжают работать в памяти.
